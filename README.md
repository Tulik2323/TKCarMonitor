# ניטור נהיגה (TKCarMonitor)

מערכת לניטור נהיגה של נהג צעיר. טלפון Android ייעודי מותקן ברכב שולח אירועים לשרת ב-Netlify, והדשבורד מציג אותם בדפדפן מכל מקום.

## מבנה

```
android/                    אפליקציית Android (Kotlin) שרצה בטלפון שברכב
netlify/functions/          Netlify Functions: קבלת אירועים, סנכרון לדשבורד, מחיקה יומית
netlify/functions/lib/      לוגיקת ה-API, אחסון ב-Netlify Blobs, ובדיקות ערך
public/                     הדשבורד (HTML/JS/CSS, בעברית)
test/                       בדיקות ה-API עם אחסון מדומה
```

## אירועים שמזוהים

| אירוע | מקור | ברירת מחדל |
|---|---|---|
| בלימה פתאומית | שינוי מהירות GPS | 0.4g |
| האצה חזקה | שינוי מהירות GPS | 0.35g |
| פנייה חדה / החלקה | מהירות × קצב סיבוב (ג'ירוסקופ) | 0.35g |
| מהירות מעל הגבול | מהירות GPS | 110 קמ"ש (ניתן לשינוי באפליקציה) |
| תאונה / פגיעה | תאוצה ליניארית של חיישן התאוצה | 4g |

כל סוג אירוע מוגבל לאירוע אחד בכל 10 שניות, כדי שזעזוע אחד לא ייצור עשרות התראות.

**לא נכלל:** זיהוי שימוש בטלפון של הבת עצמה. טלפון שמותקן ברכב לא רואה מה קורה במסך של הטלפון השני.

## שרת ודשבורד (Netlify)

הדשבורד ו-API רצים על Netlify, בדיוק כמו HealthDash. הנתונים נשמרים ב-Netlify Blobs. הדשבורד שואל את השרת כל 30 שניות, בלי שידור חי.

### משתני סביבה (Site configuration → Environment variables)

| שם | מה זה |
|---|---|
| `DEVICE_TOKEN` | הסיסמה שהאפליקציה בטלפון שולחת. הזינו אותה גם באפליקציה. |
| `DASHBOARD_TOKEN` | הסיסמה לכניסה לדשבורד. |
| `RETENTION_DAYS` | כמה ימים לשמור נתונים. ברירת מחדל: 14. |

צרו טוקנים אקראיים, למשל `openssl rand -hex 24`.

### פריסה

1. ב-Netlify: **Add new site → Import an existing project**, ובחרו את הריפו הזה. הענף הוא `main` (או הענף שאתם עובדים עליו).
2. הגדירו את משתני הסביבה לפני הפריסה הראשונה.
3. לאחר הפריסה, פתחו את כתובת האתר והזינו את `DASHBOARD_TOKEN`.

האתר נקרא לפי השם שתבחרו ב-Netlify. לדוגמה: `tkcar-monitor-tulik`.

### נתונים ומחיקה

- האירועים והמסלולים נשמרים לפי ימים. פונקציה מתוזמנת (`prune.mjs`) רצה פעם ביום ומוחקת ימים ישנים מ-`RETENTION_DAYS`.
- המחיקה היא לפי יום מלא, כך שהנתונים נשמרים בין 14 ל-15 ימים.

### בדיקות

```bash
npm install
npm test
```

הבדיקות משתמשות באחסון מדומה, כך שאין צורך בחשבון Netlify.

## אפליקציית Android

### בנייה

הפרויקט נכתב עם Android Gradle Plugin 8.5 ו-Kotlin 1.9. נדרש Android Studio (או Android SDK עם API 34).

1. פתחו את התיקייה `android/` ב-Android Studio.
2. הריצו `gradle wrapper` פעם אחת כדי ליצור את ה-wrapper (הוא לא נשמר במאגר).
3. בנייה: `./gradlew assembleDebug`. בדיקות יחידה: `./gradlew testDebugUnitTest`.

### התקנה בטלפון ברכב

1. התקינו את ה-APK על טלפון Android 11 ומעלה, והכניסו SIM עם חבילת דאטה.
2. פתחו את האפליקציה, הזינו את כתובת האתר ב-Netlify (`https://...`), את `DEVICE_TOKEN` ואת המהירות המותרת, ולחצו **שמור והפעל ניטור**.
3. אשרו הרשאת מיקום ("בזמן השימוש באפליקציה" מספיק) והתראות.
4. **חשוב:** בהגדרות הטלפון, כבו את "אופטימיזציית סוללה" לאפליקציה (Settings → Apps → ניטור נהיגה → Battery → Unrestricted). בלי זה אנדרואיד עלול לעצור את השירות.
5. חברו את הטלפון לחשמל והצמידו אותו למחזיק לשמשה.

### הפעלה מחדש

אחרי הפעלה מחדש של הטלפון, השירות מתחיל אוטומטית אם הניטור היה פעיל. ב-Android 12 ומעלה ייתכן שהמערכת תחסום זאת. במקרה כזה פתחו את האפליקציה ידנית.

## הגבלות ידועות

- **תאונה:** הזיהוי מבוסס על חיישן הטלפון במחזיק. זעזועים חזקים מכביש גס עלולים להיספר כתאונה (זיהוי שגוי). אפשר להעלות את הסף ב-`DrivingDetector.kt`.
- **מהירות:** GPS לא תמיד מדויק, במיוחד בתוך מנהרות או בין בניינים גבוהים.
- **דאטה ללא קליטה:** אירועים נשמרים במכשיר ונשלחים כשהחיבור חוזר. אין הגבלה על גודל התור.
- **עדכון כל 30 שניות:** הדשבורד לא מציג אירועים בזמן אמת, אלא עם עיכוב של עד חצי דקה.
